`heimdall tasks` shows the open tasks of norn per project, each project with
its repository, as trees of what unblocks what. Given the id of a task, it
shows that task in full. Tasks Claude added on its own come first, until they
are approved; shelved projects are left out.

[source,bash]
----
heimdall tasks                          # every open task
heimdall tasks freyja                   # the open tasks of a project
heimdall tasks freyja/gpu               # or of an area
heimdall tasks freyja/gpu/mesh-store    # one task in full
heimdall tasks -a                       # shelved projects too
----

A tree starts at a task that waits on nothing open in its project and branches
to the tasks it unblocks. The hours are what is left of the estimate. A task
that waits on two others is under both; the second time, `↑ above` points to
the first.

A task that waits on another project names it in orange, `needs lib/core`,
before its title. A project whose repository Heimdall does not track says `no
repository`; link:configuration.html[`projects`] names it.

Projects follow their most urgent task, and a tree its tasks by priority. Two
columns appear only when a task in view needs them:

* the priority, when it is not the usual 2 (1 is high, 3 low), and `✦` for a
  task Claude added on its own;
* the tokens: `~60k` estimated, or `80k/60k` spent of the estimate.

A task Claude adds on its own waits for approval in the first block; one it adds
on the author's word counts as the author's. A shelved project shows as a count
in the header, unless `-a` is given or the prefix is inside it.

== Tokens

The tokens a task spent are read from the transcripts of the Claude sessions
linked to it in norn, `norn.py task session <id>`, subagents included. They are
new input, cache writes and output; cache reads, which repeat the context on
every answer, are left out. A session linked to several tasks counts for each
an equal share.

_Waits on_ is the whole chain, done tasks included, and its hours are what is
left of every open task in it. _Unblocks_ follows the open tasks only. The
estimate shows the original one too when it was changed, and how often the task
was moved when it was.
